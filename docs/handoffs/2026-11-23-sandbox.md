## 4. Decisions that need your call

1. **Unchecked means hands-off at Quit, even when the only problem is a
   missing store entry.** If the store can't be read, Phases leaves *every*
   display's wallpaper alone at Quit. Your original wallpaper won't come
   back, but no Aerial gets flattened. The same happens for a display with
   no entry in the store, such as a newly connected one. *Recommendation:*
   keep it. The other direction is the bug the prompt describes. If the
   exception works (check 2), unchecked should be rare.
2. **Read-only bookmarks and old bookmarks.** New bookmarks are made
   read-only to match the read-only entitlement. Bookmarks your unsandboxed
   build saved are read-write, and may not open in the sandbox at all
   (*hypothesis*). If they don't, each folder source shows "Can't open" and
   Locate… re-picks it with its ID kept, so selections come back.
   *Recommendation:* accept a one-time Locate… per source rather than
   asking for read-write.
3. **A location-only folder now shows "Can't open"** when Phases can't list
   it, instead of looking empty. Unsandboxed, this also catches a folder
   macOS privacy refuses. *Recommendation:* keep it. It's what SPEC.md
   already says a source that can't be opened looks like.
4. **The old photo cache** (`~/Library/Application Support/Phases/Photos/`)
   stays behind, and the sandboxed build starts a new cache in its
   container. *Recommendation:* leave it. Delete it by hand later (follow-up
   below). Moving it automatically would need a container migration plist,
   which isn't worth it for one user.
5. **`bitrig test` vs `swift test`:** see section 3. *Recommendation:*
   allow `swift test` in `UnitTests/` in future prompts. It's the
   documented route, and `bitrig` can't run this package.
6. **`files.bookmarks.app-scope`:** I added it because Apple's docs say
   it's needed. If you'd rather test without it first, it's one line to
   drop. *Recommendation:* keep it. It's harmless, and a missing one would
   show up only as lost folders after a relaunch.

## 5. Hands-on checks (only you can run these)

Approve as one set. Each needs a launch, and checks 4 to 6 drive the
desktop by hand. Run them on a build from `feature/19-sandbox` with
diagnostics on. **Do step 1 before anything else.**

1. **Back up preferences, then launch for the first time.** With Phases
   quit:
   `cp ~/Library/Preferences/app.bitrig.new.ecd0db30-b411-4419-8736-9fe3d1c96268.plist ~/Desktop/`.
   Turn on diagnostics (`defaults write app.bitrig.new.ecd0db30-b411-4419-8736-9fe3d1c96268 PhasesDiagnostics -bool true`;
   macOS moves it into the container along with the rest). Launch. Confirm
   that `~/Library/Containers/app.bitrig.new.ecd0db30-…/Data/Library/Preferences/`
   now holds the plist and your phases appear as before.
2. **Aerials left alone.** Before launching, put an Aerial on one display
   and a still on another. In the log (`/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "PhasesDiag"'`),
   there should be **no** "can't read the wallpaper store" line in
   `restore` or `store`, and `store` should say "watching the store: N
   entries". Quit with Restore on. The Aerial display should log "left
   alone on quit: system wallpaper", and the still display should log
   "restored". This is the check that proves the exception works.
3. **Folder source after relaunch.** Check whether each folder source
   opens or shows "Can't open" (decision 2). If "Can't open", use Locate….
   Then quit and relaunch: the log should say "found by its bookmark", and
   thumbnails and changes should work.
4. **Photos source.** Allow Photos when asked (expected: a new build asks
   again). Change Now onto a Photos phase, including one iCloud-only photo
   if you have one handy. If the iCloud photo fails while local ones work,
   `network.client` is the suspect.
5. **Crossfade after a Space switch and a display change.** Crossfade on.
   Change Now, switch Spaces and back, then change a display's resolution.
   The cover should redraw with no "cover: no surface" line in the
   `cover` log.
6. **Restore on quit** from an original outside every source (for example
   `/System/Library/Desktop Pictures/…` or a file in `~/Downloads`). It
   should come back, and the log should say "restored", not "file no
   longer exists".
7. **A link pointing outside the folder.** Put a symlink or alias in a
   source folder pointing at an image elsewhere. Expected: the image is
   missing from the grid, and `sources` logs "not permitted to read
   <name>". A link to an image *inside* the folder should still show.
8. **Location prompt.** Use a dawn/dusk phase. Expected: macOS may ask
   again, and dawn and dusk show in Settings once allowed.
9. **Outside change and unlock.** Pick a wallpaper in System Settings:
   Phases should pause (the store watcher works through the exception).
   Lock and unlock: a missed change should apply
   (`com.apple.screenIsUnlocked` reaches the sandbox).
10. **Going back** (only if you want to try it). Follow SPEC.md
    `[D-sandbox-settings-move]` "Going back to an unsandboxed build" step
    by step. Those steps are untested, so record what actually happens.
    The `~/Desktop` backup from step 1 is the fallback.

Results go in SPEC.md as *Verified* notes, and in LEARNINGS/EXPERIMENTS
for anything surprising.
